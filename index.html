🔁 Universal Analytics Pipeline
1
Define the question
Predict? Classify? Cluster? Optimize? This determines everything else.
2
Load & explore data
Check distributions, missing values, outliers, data types.
3
Remove outliers
BEFORE scaling. Outliers distort scale.
4
Impute missing + scale
Mean/regression/flag imputation. Normalize/standardize for distance-based models.
5
Variable selection
Lasso, PCA, or stepwise on all candidate variables. Fit on training only.
6
Fit candidate models
Train multiple models on training set with selected variables.
7
Select model via validation
Compare on held-out validation set. Prefer simpler when performance ≈ equal.
8
Evaluate on test set
Report test error. Never touch test set until final model is chosen.

🏷️ Classification Pipeline
CLASSIFY
1
Prep data
Universal pipeline steps 1–5 above
2
Choose model(s)
Try SVM, RF, logistic reg. Pick based on data size & need for probability output
3
Set threshold
Default = 0.5. Adjust based on cost of FP vs FN.
4
Evaluate
Total cost = (#FP × cost_FP) + (#FN × cost_FN). Not just accuracy.
High FP cost → raise threshold (be conservative). High FN cost → lower threshold (catch more).

Support Vector Machine
Classification via maximum-margin boundary
Key Concepts
Hard margin
No errors allowed — perfect separation
Soft margin
Errors allowed, controlled by C
Margin
Distance to nearest pts. Wider = simpler.
Misclassified ≠ outlier
Misclassified = wrong side of boundary
ParameterEffect
C ↑Margin ↓, errors ↓, overfit ↑
C ↓Margin ↑, errors ↑, generalization ↑
Kernel complexity ↑Params ↑, overfit risk ↑
Shifting from equal margin → MORE errors on val+test, not fewer.
When to use
Use SVM when
High-dim data, clear margin, not needing probability output
Use Logistic when
Need P(class) for threshold tuning / cost optimization
Equal margin
When FP cost = FN cost
Vertical boundary
Only x-axis variable matters

  pred <- ifelse(probs >= t, 1, 0)

Linear Regression
Predict continuous response. Add interaction terms and quadratics to extend.
Key Concepts
Quadratic term
Add x² AND keep x (both needed for U-shape)
Interaction xi·xj
Neg. coeff = combined effect < sum of parts
AIC/BIC
Lower = better. Gap > 10 = strong evidence. BIC penalizes complexity more.
AIC ratio
e^((AICi − AICj)/2) = times more likely model j vs i
Regression = predictive. NOT prescriptive (needs optimization layer for that).

Lasso / Ridge / Elastic Net
Regularized regression for variable selection and overfit prevention
Quick Reference
MethodPenaltyVariables keptUse when
Lasso (L1)λΣ|βj|FEWEST — zeros some outSparse model, variable selection
Ridge (L2)λΣβj²MOST — shrinks allAll vars contribute a little
Elastic Netλ1Σ|βj| + λ2Σβj²MIDDLEGroups of correlated vars
λ ↑ → more regularization, fewer/smaller coefficients, less overfit. λ ↓ → more vars, more overfit risk.

Exponential Smoothing & Holt-Winters
Forecast time series with trend and seasonality
Key Formulas
Simple: St = α·xt + (1−α)·St-1
HW baseline: α(xt/Ct-L) + (1−α)(St-1 + Tt-1)
HW trend: β(St − St-1) + (1−β)Tt-1
HW season: γ(xt/St) + (1−γ)Ct-L
ParameterEffect
α → 1Trust current observation, adapts fast (low noise)
α → 0Trust historical average, slow adapt (high noise)
β, γ → 1Trend/season react quickly to recent data
β, γ → 0Trend/season very stable, change slowly

CUSUM — Change Detection
Detect when a process has shifted. Faster than hypothesis tests. Apply to any derived series.
Key Concepts
CUSUM T ↑
SLOWER to detect — both true changes and false alarms
CUSUM T ↓
FASTER to detect — but more false alarms too
Apply to
Raw series, seasonal multipliers Ct, annual regression coefficients, residuals
Code
library(qcc)

# CUSUM chart on a series
cusum_chart <- cusum(series, newdata = NULL,
                     decision.interval = 4,  # T threshold (h)
                     se.shift = 1)           # shift to detect (in std devs)
plot(cusum_chart)

# Manual CUSUM (more control)
cusum_manual <- function(x, mu0, sigma, k = 0.5, h = 4) {
  Cu <- Cl <- numeric(length(x))
  for (i in 2:length(x)) {
    Cu[i] <- max(0, Cu[i-1] + (x[i] - mu0) / sigma - k)
    Cl[i] <- max(0, Cl[i-1] - (x[i] - mu0) / sigma - k)
  }
  change_pts <- which(Cu > h | Cl > h)
  list(Cu = Cu, Cl = Cl, change_pts = change_pts)
}
result <- cusum_manual(series, mu0 = mean(series), sigma = sd(series))
import numpy as np
import matplotlib.pyplot as plt

def cusum(x, mu0=None, sigma=None, k=0.5, h=4):
    """CUSUM chart. h = threshold (↑ = slower, more conservative)."""
    if mu0 is None: mu0 = np.mean(x)
    if sigma is None: sigma = np.std(x)
    Cu, Cl = np.zeros(len(x)), np.zeros(len(x))
    for i in range(1, len(x)):
        Cu[i] = max(0, Cu[i-1] + (x[i] - mu0)/sigma - k)
        Cl[i] = max(0, Cl[i-1] - (x[i] - mu0)/sigma - k)
    change_pts = np.where((Cu > h) | (Cl > h))[0]
    return Cu, Cl, change_pts

Cu, Cl, changes = cusum(series, h=4)

Logical Constraints Cheat Sheet
LogicConstraint
If A then ByB ≥ yA
If A then B or CyB + yC ≥ yA
Exactly one of A, ByA + yB = 1
At least one of A, ByA + yB ≥ 1
At most one of A, ByA + yB ≤ 1
Neither A nor ByA = 0, yB = 0
Amount only if facility openxi ≤ U·yi (U = big-M)

Simulation & Queuing
Model systems under randomness. ρ = λ/(s·μ). If ρ ≥ 1, queue grows without bound.
Queuing Formula
ρ = λ / (s · μ) where: λ = arrival rate, s = # servers, μ = 1/avg_service_time
ParameterEffect
λ (arrivals) ↑ρ ↑, wait times ↑
s (servers) ↑ρ ↓, wait times ↓
Service time ↑μ ↓, ρ ↑, waits ↑
ρ ≥ 1Queue grows without bound → HIGH waits
Run MANY simulations. One run is misleading. Stop when the running average stabilizes.
Code

import simpy      # pip install simpy
import numpy as np
import random

lam = 4   # arrivals/hr
mu  = 5   # service rate/hr
rho = lam / mu; print(f"ρ = {rho:.2f}")  # must be < 1

wait_times = []

def customer(env, server, arrival_time):
    with server.request() as req:
        yield req
        wait_times.append(env.now - arrival_time)
        yield env.timeout(random.expovariate(mu))

def arrivals(env, server):
    while True:
        yield env.timeout(random.expovariate(lam))
        env.process(customer(env, server, env.now))

# Run many replications
all_waits = []
for _ in range(100):
    wait_times = []
    env = simpy.Environment()
    server = simpy.Resource(env, capacity=1)
    env.process(arrivals(env, server))
    env.run(until=1000)
    all_waits.append(np.mean(wait_times))
print(f"Avg wait: {np.mean(all_waits):.3f}")
Detecting & Treating Outliers
Always remove outliers BEFORE scaling. Outliers distort scale and cluster centers.
When to remove vs. keep
SituationActionWhy
Data entry error (e.g. age = 999)Remove or correctNot a real observation
Legitimate but extreme (e.g. $1B sale)Keep — or model separatelyReal signal; removing distorts the distribution
For clusteringRemove first, then scaleOutlier pulls cluster centers; distorts distances
For regressionInvestigate — consider robust regressionHigh-leverage points can dominate the fit
For SVM/KNNRemove if clearly erroneousDistance-based models are sensitive to outliers
Outlier ≠ misclassified. An outlier is far from others in feature space. A misclassified point is on the wrong side of a decision boundary.
Detection Methods
MethodRuleBest for
IQR methodBelow Q1 − 1.5×IQR or above Q3 + 1.5×IQRGeneral use; robust to skew
Z-score|z| > 3 (i.e. > 3 std devs from mean)Roughly normal distributions
Visual (boxplot)Points beyond whiskersQuick check on individual columns
Isolation ForestML-based; anomaly score per pointHigh-dimensional data, multivariate outliers
LOF (Local Outlier Factor)Density-based local anomaly scoreWhen outliers are relative to local neighborhood
Mahalanobis distanceDistance accounting for correlations between varsMultivariate normal data

Missing Data
Choose strategy based on whether the value is predictable and whether the reason for missingness is informative.
Decision Tree — Which Strategy?
1
Is the missing value predictable from other columns?
→ YES: use regression imputation. → NO: go to step 2.
2
Can you classify WHY it's missing?
→ YES: use two-stage imputation (classify reason → impute per reason). → NO: go to step 3.
3
Is the fact that it's missing informative?
→ YES: add binary flag column (0 = present, 1 = missing). → NO: mean impute as baseline.
StrategyWhen to useLimitation
Mean/median imputeSimple baseline; value not predictableUnderestimates variance; ignores relationships
Regression imputeValue IS predictable from other varsAssumes correct model; inflates R²
Two-stage imputeReason for missing classifiable; value predictableMore complex; requires enough data per class
Binary flag (0/1)Missingness itself is informativeDoesn't recover the value
Multiple imputation (MICE)Want uncertainty-aware imputationComputationally expensive
Drop rowVery few missing; missingness is randomReduces data; biased if not MCAR
Drop column>60–70% missing with no salvageable signalLoses potentially useful variable
Missing mechanisms: MCAR (Missing Completely At Random — safe to drop), MAR (Missing At Random — impute), MNAR (Missing Not At Random — flag + impute).
